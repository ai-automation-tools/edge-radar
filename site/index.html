Open source · Kalshi · sports and prediction markets · dry run by default

Research first. Execute second.

Edge-Radar compares Kalshi's price against an independent fair value built from sportsbook consensus and public data feeds. A bet fires only when the gap clears the exchange fee and every risk gate, and it is sized by fractional Kelly.

Not financial advice. The repository documents its losing segments as carefully as its winning ones, and the model's own calibration study says the market is usually right.

How it works

One equation, guarded by 21 gates.

Pull Kalshi's ask. Pull an independent fair value from sportsbooks and data feeds. The difference is the claimed edge. The exchange fee comes off before anything else is judged, and only then does the order meet the gates.

fair_value − market_ask = edge · edge − fee(price) ≥ floor and every gate passes → bet

Risk gates

Every order meets 21 gates. Most candidates fail here, cheaply.

The chain runs in order before any order is placed. Reject drops the bet, Cap trims it. Gates that read a market fact fail open when the fact is missing; the venue-eligibility check fails closed.

No gate matches that. Clear the filter or try another word.

Before the chain: venue eligibility, fails closedA live order needs a recorded ok for the venue and product. unknown blocks exactly like blocked; a structural rejection aborts the batch and nothing clears it automatically.
After the chain: the 10% hard stopThe last step of sizing caps any single position at 10% of bankroll and rejects it if even one contract would breach. Enforced in code, not only in the rules.

Pipeline

Seven stages. Scan, size, execute, settle.

One entry point, scripts/scan.py, runs the chain for sports, futures or prediction markets. A preview stops after stage 5 and prints what the gates said about every row it saw.

01FetchKalshi markets and order books, plus the Odds API and data feeds, through a short-TTL cache.
02CategorizeTicker → market type. ML · SP · TO · FU · PR each pick a model.
03CompareFair value against the ask, net of fee, with a confidence tier and a composite score.
04CapBracket dedup keeps the sibling that can clear the gates; per-event caps apply.
05Risk21 gates in order. Reject or trim. Preview prints the verdicts.
06ExecuteFractional Kelly size, shard funding, RSA-signed limit order. Dry run logs identically.
07SettleOutcomes, measured fees, Brier pair, drift and post-kickoff alarms. make settle

Coverage

What the scanner prices.

Each segment carries its own edge floor, and a floor of 1.0 is the idiom for switching a segment off. A segment with no settled history runs in dry run or on a pilot floor until it has evidence.

Sports

Moneylines, spreads, totals

Sportsbook consensus, de-vigged and weighted by book tier, against Kalshi's game markets. Thirty-one game filters across the major leagues, college, soccer, combat sports, motorsport, golf, tennis and esports.

Prediction

Crypto, weather, S&P 500

Spot and volatility from CoinGecko, National Weather Service forecasts for thirteen cities, and index levels from Yahoo Finance, each turned into a probability for the bracket Kalshi lists.

Futures

Championship outrights

Outright odds across books, de-vigged into a field that sums to one, against each team's title market. Outcomes partition one event, so the per-event cap is its own knob.

Quick start

Clone, validate, preview. Nothing is risked.

Python 3.11 or later. A preview places nothing, and DRY_RUN=true is the default even with --execute, so the first live order is a decision you make in .env, not a side effect.
